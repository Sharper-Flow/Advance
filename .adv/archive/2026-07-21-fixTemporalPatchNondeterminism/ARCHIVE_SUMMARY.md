## Wisdom Accumulated

- **[gotcha]** Temporal patched() ordering model: wf.patched(id) does NOT occupy an immutable command index. sdk-core can SKIP a patch command absent from history — inserting patched("B") above existing patched("A") does NOT by itself fail replay of a history containing only A. TMPRL1100 "Non-deprecated patch marker ... no corresponding change command" fires when (a) a recorded nondeprecated marker has no REACHABLE patch command on the current path, or (b) actual command-producing operations (Activity/timer/UpsertWorkflowSearchAttributes) shift incompatibly AROUND the marker. Patch-to-patch ordering alone is not nondeterminism. Forward-drift regression must cross a real Activity/timer/upsert boundary, not merely insert/reorder patch calls. Source: github.com/temporalio/sdk-core workflow_machines.rs#L1737-L1794, patch_state_machine.rs; adv-researcher validation 2026-07-20.
- **[gotcha]** Temporal deprecatePatch lifecycle: the SDK-blessed sequence is patched(oldId) → deprecatePatch(oldId) [after pre-patch executions are gone] → remove. deprecatePatch(oldId)+patched(newId-v2) is NOT a generic "relocate/change old branch" recipe — v2 is for a SEPARATE incompatible change. Deprecating oldId before all live pre-oldId histories are gone is unsafe. During replay, deprecatePatch(oldId) emits the matching internal patch command for histories that recorded it, without appending a fresh event. Source: docs.temporal.io/develop/typescript/workflows/versioning; sdk-typescript internals.ts#L1198-L1212.
- **[gotcha]** Advance worker-bundle manifest ALREADY EXISTS at dist/temporal/bundle-manifest.json (generated by pnpm run build:worker), with reader at plugin/src/temporal/worker-bundle-manifest.ts. The freshness gap is NOT a missing manifest — it's that (a) the reader doesn't rehash workflows.js + worker.js against the manifest, (b) worker startup doesn't verify the manifest before Worker.create (workflowsPath loads during create, not run — verification must happen BEFORE create), (c) deploy-local.sh publishes the plugin manifest last/atomically but lets the worker manifest travel in the general rsync payload without equivalent hash verification. Also: the manifest hashes workflowsPath INPUT, but Worker.create compiles that path — doesn't prove final in-memory bundle identity; production guidance prefers prebuilt workflowBundle. Dev fallback loads workflows.ts when workflows.js absent — manifest enforcement must distinguish production from dev.
