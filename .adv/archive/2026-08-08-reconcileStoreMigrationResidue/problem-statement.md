# Problem Statement

## Incident
The Advance plugin removed its Temporal backing and made on-disk projections the sole authority (`c231b2eb complete Temporal removal`, `05907bbc remove Temporal read paths`, `ab300f93 bypass Temporal signal dispatch`, `0d565876 delete replay-determinism test infrastructure`). The migration completed before all records were reconciled to disk. An affected consumer project (pokeedge) reports `canonical_projection_consistent: false` with divergences beyond doctor's scan budget (64 projections / 1500ms; 200 omitted — more likely remain), a degraded summary index, legacy-envelope divergence (worst case: canonical rev 99 vs legacy rev 0), `unmigrated: 9` with `migration_status: null`, one quarantined schema-drifted change, and four Epic owner records lost (`strengthenDataModelIntegrity`, `pricingIdentityIntegrity`, `collectionSellTradeMarkers`, `strengthenCrossRepoBrowserConfidence`) — orphaning ~9 active changes whose only surviving Epic evidence is child-side `epic_membership` fragments.

## Root Cause Analysis
Temporal was deleted before a reconciliation pass existed, and no reconcile command was ever built. Verified against the codebase: the relevant internal modules (`change-summary-shard.ts`, `artifact-metadata-migration.ts`, `session-registry.ts`, `launcher-projection.ts`) are operation-scoped library code; `adv_doctor` repairs only session pointers and dead worker locks (`tools/doctor.ts:430,367`) with everything else report-only; no legacy→canonical envelope writer exists anywhere (`projection-health.ts:182` is read-only comparison); Epic convergence flows Epic→child only (`epic-convergence.ts`) with no child-fragment→Epic reconstruction path; `reconcileHistoricalArchiveDeltas` is an orphan export reconciling archive-delta/spec baselines, not store envelopes. `adv_launcher_projection_rebuild` does regenerate per-change summary shards from canonical `change.json` before building the aggregate (`tools/launcher-projection.ts:36-49`) — a latent repair path for the summary-pointer class, but unexposed standalone and unable to handle records that fail canonical parse.

## Why this cannot self-heal
No exposed command completes migrations store-wide, reconciles envelopes, normalizes schema drift, or backfills Epics. `bin/adv` is read-only diagnostics. The one schema-drift exemplar (`optimizeArchitectureTestSuite`, retired `evidence_kind` values) was quarantined, not normalized.

## Required Outcome
A runnable, idempotent, dry-run-first reconciliation pass that brings the disk store to `canonical_projection_consistent: true`, completes pending migrations, normalizes schema-drifted records, and either restores the four lost Epics from surviving fragments (with reconstruction provenance + gap flags) or reconciles them as formally lost with dangling memberships cleaned up. Disk evidence (and ADV-store git history, if any) only — Temporal is gone.
